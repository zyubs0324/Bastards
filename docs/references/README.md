## 원칙

- **P1 코어는 판정 축, 스택은 표기.** 코어 6종은 "무엇이 결함인가"를 아래 논리명으로만 서술한다. 논리명이 실제 코드에서 무엇인지는 스택 문서 §1~§6 이 정한다.
- **P2 판정 절 = 번호 + 판정 불릿.** 판정 절은 번호가 붙고 본문에 `- **Flag:**`(comments 는 `REMOVE`/`REVISE`/`KEEP`/`ADD`) 불릿이 있다. `- **Note:**` 는 위임·제외 표시일 뿐 판정 불릿이 아니다.
- **P3 전제 게이트.** 절 제목 바로 아래 `전제: <이름>` 줄이 있으면, 스택 문서 §0 의 해당 값이 `—` 일 때 그 절은 꺼진다. 꺼진 절은 커버리지에 `—(전제 꺼짐: <이름>)` 으로 적는다.
- **P4 단일 정본.** 스택·도구·경로 사실은 `project_facts.md` §0 과 스택 문서 §0 에만 적는다. 코어 문서와 스킬에 중복 기재하지 않는다.
- **P5 이름 금지.** 스킬 파일, 이 README, 코어 6종에 특정 언어·엔진·라이브러리 이름이 등장하면 그 자체가 결함이다. 이름은 `project_facts.md` 와 스택 문서에만 쓴다.
- **P6 규모 보정.** 이 프로젝트는 1인 개발 프로토타입 단계다. 확장성을 이유로 한 추상화 요구는 판정 근거가 되지 않는다(arch §1.8).

## 심각도

| 등급 | 기준 | Verdict 영향 |
|---|---|---|
| CRITICAL | 빌드 실패, 자격증명 유출, 규칙 모듈 경계 붕괴처럼 되돌리기 비싼 결함 | BLOCK |
| HIGH | 버그, 결정론 붕괴, 누수, 조용한 데이터 오류 | 수정 후 진행 권장 |
| MEDIUM | 유지보수성 저하, 측정 가능한 비효율 | 가능하면 수정 |
| LOW | 스타일, 사소한 제안 | 선택 |

## 공통 논리명 사전

| 논리명 | 뜻 |
|---|---|
| 규칙 모듈 | 전투 규칙 계산을 담는, 엔진에 의존하지 않는 코드 단위 |
| 표시 계층 | 화면 출력·입력 수집을 담당하는 엔진 의존 코드 |
| 데이터 로더 | 데이터 파일을 읽어 검증 후 규칙 모듈 타입으로 변환하는 코드 |
| 모듈 경계 선언 | 코드 단위 간 참조를 선언·제한하는 설정 파일 |
| 엔진 참조 차단 설정 | 규칙 모듈이 엔진 API 를 참조하지 못하게 막는 설정 |
| 진입점 객체 | 화면에 배치된 유일한 시작 객체. 나머지를 코드로 생성한다 |
| 명령 큐 | 사용자 입력이 규칙 모듈에 전달되는 경로. 대기 명령이 없으면 자동 판단이 같은 틱에 같은 형식의 명령을 만들어, 둘 다 하나의 실행 경로로 처리된다 |
| 상태 스냅샷 | 규칙 모듈 밖으로 노출되는 읽기 전용 상태 표현 |
| 고정 틱 | 프레임 속도와 무관한 규칙 계산의 시간 단위 |
| 시드 난수 | 시드로 재현 가능한, 주입받는 난수 공급자 |
| 데이터 파일 | 밸런스 수치·캐릭터·장비·스테이지를 담는 텍스트 파일 |
| 프레임 콜백 | 매 프레임 호출되는 엔진 콜백 |
| 컴포넌트 탐색 호출 | 실행 중 객체·컴포넌트를 검색하는 호출 |
| 힙 할당 | 가비지 수집 대상 메모리를 새로 만드는 연산 |
| 객체 생성·파괴 호출 | 화면 객체를 실행 중 만들고 없애는 호출 |
| UI 재구성 | 텍스트·레이아웃 변경으로 UI 메시 재계산을 유발하는 연산 |
| 로그 호출 | 콘솔·로그 출력 호출 |
| 개발 전용 구역 | 개발 빌드에서만 컴파일되는 코드 구역 |
| 에디터 노출 필드 | 편집기에서 값을 설정하도록 노출한 필드 |
| 상수 선언 | 컴파일 시점·초기화 시점에 고정되는 값 선언 |
| 서명 키 파일 | 앱 배포 서명에 쓰는 키 저장 파일 |
| 자격증명 파일 | 스토어·서비스 계정 비밀 정보를 담는 파일 |
| 무시 목록 | 버전 관리에서 제외할 경로 목록 |
| 서드파티 의존성 목록 | 외부 패키지와 버전을 선언한 파일 |
| 테스트 모듈 | 자동 테스트 코드 단위와 그 모듈 경계 선언 |

## 공통 출력 규칙

- 각 코어 문서의 "출력 형식" 절이 필드 이름의 정본이다.
- 모든 발견은 **심각도 · 위치(`파일:라인` 또는 `문서:절`) · 근거(어느 절에 왜 해당하는지) · 제안(무엇을 할지)** 을 담는다.
- 발견 뒤에 SKILL.md §검사 커버리지 형식의 커버리지 블록을 붙인다.

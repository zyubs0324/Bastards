# 주석 기준 (scope: comments)

> 논리명의 실제 표기는 활성 스택 문서 §6 을 따릅니다. 판정은 REMOVE(삭제) · REVISE(수정) · KEEP(유지) · ADD(추가) 로 매깁니다.

## 핵심 보정 원칙

- 주석은 **코드가 말하지 못하는 것**(이유, 출처, 함정)만 적는다. 코드가 무엇을 하는지 되풀이하는 주석은 부패의 씨앗이다.
- 이 프로젝트의 규칙은 기획서에서 온다. 규칙 구현부의 기획 참조 주석은 비개발자가 코드와 기획을 오가게 해 주는 유일한 연결 고리라 가치가 크다.
- 주석 밀도는 주변 코드에 맞춘다. 파일 하나만 유독 빽빽하거나 비어 있으면 그 자체로 신호다.

## 1. 코드를 되풀이하는 주석
- **REMOVE:** 바로 아래 코드의 동작을 그대로 말로 옮긴 주석(예: "체력을 1 줄인다").
- **REMOVE:** 이름만으로 뜻이 분명한 멤버에 붙은 문서 주석.

## 2. 부패한 주석
- **REVISE:** 코드와 내용이 어긋나는 주석(바뀐 공식·옛 이름·삭제된 매개변수 언급). 동작 오해를 부르므로 우선 처리한다.
- **REVISE:** 용어집(`project_facts.md` §0-B)과 다른 용어를 쓰는 주석.

## 3. 기획 참조 주석
- **REVISE:** 기획 참조 주석이 존재하지 않는 절, 또는 내용이 달라진 절을 가리킴.
- **ADD:** 기획서 공식·판정을 구현한 함수에 기획 참조 주석이 없음.
- **REMOVE:** 기획 문서의 긴 문단을 주석으로 복사해 둠(참조 한 줄로 대체).

## 4. 이유 주석
- **ADD:** 직관에 반하는 결정(불변성 예외, 정수 연산 선택, 특정 순서 의존)에 이유가 없음.
- **ADD:** 스택의 함정을 피하려고 일부러 쓴 코드(예: 특정 null 비교 방식)에 이유가 없음.
- **KEEP:** 짧게 "왜"를 설명하는 주석.

## 5. 잔재
- **REMOVE:** 주석 처리된 코드.
- **REMOVE:** 변경 이력·날짜·작성자 주석(버전 관리가 기록한다).

## 6. 할 일 표기와 문서 주석 범위
- **REVISE:** 조건·범위 없이 막연한 할 일 표기(예: "나중에 고치기"). 무엇이 끝나면 할지 적는다.
- **REMOVE:** 활성 계획 문서에서 이미 끝난 작업을 가리키는 할 일 표기.
- **ADD:** 규칙 모듈의 공개 타입·메서드 중 사용 조건(단위, 범위, 부작용)이 이름으로 드러나지 않는 것에 문서 주석이 없음.
- **REMOVE:** 표시 계층의 비공개·사소한 멤버에 붙은 형식적 문서 주석.

## 7. 출력 형식

```
- [REMOVE|REVISE|ADD] `파일:라인` — 위반 절(§N) · 한 줄 사유
  제안: 바꿀 문구 또는 삭제
```

REMOVE/REVISE 후보는 메인 에이전트가 사용자 승인 후 직접 반영한다(SKILL.md 코드 모드 Step 5). 발견 뒤에 SKILL.md §검사 커버리지 형식의 블록을 붙인다. 이 문서의 판정 절은 §1~§6, 비판정 절은 §7 이다.

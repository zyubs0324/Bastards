# 성능 기준 (scope: perf)

> 논리명의 실제 표기는 활성 스택 문서 §4 를 따릅니다. 심각도 정의는 `README.md` 입니다.

## 0. 핵심 보정 원칙

- 목표는 중급 안드로이드 기기에서 전투 화면이 끊김 없이(30fps 이상 안정) 도는 것이다.
- 판정 대상은 **반복 경로**(프레임 콜백, 틱 처리, 유닛·이펙트 수에 비례하는 루프)다. 한 번만 도는 초기화 코드의 비용은 대부분 LOW 이하다.
- 측정 없이 "느릴 것 같다"는 추측은 보고하지 않는다. 반복 빈도와 규모를 근거로 든다.
- 아키텍처·arch 와 lang 에서 위임된 누수·메인 스레드 판정은 이 문서가 맡는다.

## 1. 판정 기준

### 1.1 반복 경로의 힙 할당
- **Flag:** 프레임 콜백이나 틱 처리 안의 힙 할당(컬렉션 생성, 문자열 조합, 캡처 람다, 박싱, 질의 연산자) → HIGH.
- **Flag:** 사용자 입력·전투 종료처럼 드문 경로의 할당 → LOW.

### 1.2 반복 경로의 탐색 호출
- **Flag:** 프레임 콜백이나 틱 처리 안의 컴포넌트 탐색 호출 → HIGH. 생성 시점에 참조를 보관한다.

### 1.3 객체 생성·파괴 반복
- **Flag:** 데미지 숫자·이펙트처럼 자주 생기는 표시 객체를 매번 생성·파괴 호출 → MEDIUM. 재사용 풀을 쓴다.

### 1.4 UI 재구성
- **Flag:** 값이 바뀌지 않았는데 매 프레임 텍스트·레이아웃을 다시 설정 → MEDIUM. 값이 바뀔 때만 갱신한다.
- **Flag:** 자주 바뀌는 요소(게이지·숫자)와 정적 요소가 같은 재구성 단위에 묶임 → LOW.

### 1.5 시뮬레이션 비용
- **Flag:** 틱마다 전체 전투 상태를 복사 → HIGH (활성 계획 문서에서 기각된 방식).
- **Flag:** 틱마다 유닛 수의 제곱 이상으로 도는 탐색 → 유닛 10명 이하이면 LOW, 그 이상을 전제로 하면 MEDIUM.
- **Flag:** 배속 시 프레임당 틱 호출 횟수에 상한이 없어 프레임이 밀리면 틱이 폭증 → MEDIUM.

### 1.6 누수
- **Flag:** 이벤트 구독 후 해제 누락, 파괴된 객체를 정적·장수 컬렉션에 보관, 정지하지 않는 반복 작업 → HIGH.
- **Flag:** 전투 재시작 때 이전 전투의 표시 객체·구독이 남음 → HIGH.

### 1.7 메인 스레드 블로킹
전제: 스레딩 모델
- **Flag:** 전투 중(프레임 진행 중) 동기 로딩·파일 입출력 수행 → MEDIUM. 로딩은 전투 시작 전에 끝낸다.
- **Flag:** 시작 시 동기 로딩이 데이터 규모 대비 과함(수 MB 이상) → LOW.

### 1.8 드로우 콜
- **Flag:** 유닛·UI 요소마다 재질을 복제·생성해 배칭이 깨짐 → MEDIUM.

### 1.9 로그 비용
- **Flag:** 반복 경로의 로그 호출이 개발 전용 구역 밖에 있음 → MEDIUM.

## 2. 출력 형식

```
### [CRITICAL|HIGH|MEDIUM|LOW] 한 줄 제목
- 위치: `파일:라인`
- 근거: 해당 판정 절(§1.x), 반복 빈도(프레임/틱/전투당)와 규모
- 제안: 무엇을 해야 하는지
```

발견 뒤에 SKILL.md §검사 커버리지 형식의 블록을 붙인다. 이 문서의 판정 절은 §1.1~§1.9, 비판정 절은 §0·§1(컨테이너)·§2 이다.

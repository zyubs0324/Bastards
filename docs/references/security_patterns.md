# 보안 기준 (scope: security)

> 논리명의 실제 표기는 활성 스택 문서 §3 을 따릅니다. 심각도 정의는 `README.md` 입니다.

## 핵심 보정 원칙

- 이 프로젝트는 서버·계정·결제가 없는 1회 구매 단일 플레이 게임이다. 위협 모델이 작으므로 **실제 위험이 있는 것만** 보고한다.
- 가장 큰 실제 위험은 (1) 배포 서명 키·스토어 자격증명 유출, (2) 잘못된 데이터 파일로 인한 크래시·무한 루프다.
- 전제가 꺼진 절(네트워크·계정·영속 저장)은 판정하지 않는다(README P3).

### 1. 서명 키·자격증명 커밋
- **Flag:** 서명 키 파일 또는 자격증명 파일이 저장소에 추가되거나, 무시 목록에서 빠짐 → CRITICAL.
- **Flag:** 서명 비밀번호·스토어 계정 비밀번호·API 키가 코드·빌드 스크립트·설정 파일에 평문으로 있음 → CRITICAL.
- **Flag:** 무시 목록에 서명 키 파일 패턴이 없음 → HIGH.

### 2. 비밀 정보의 로그·오류 노출
- **Flag:** 비밀번호·키 경로·계정 정보를 로그 호출이나 오류 메시지로 출력 → HIGH.

### 3. 외부 데이터 파일 신뢰
- **Flag:** 데이터 파일 역직렬화 결과를 범위·필수 필드·참조 검증 없이 규칙 모듈에 전달 → HIGH. 음수 체력, 0 나눗셈, 존재하지 않는 ID 로 크래시하거나 전투가 끝나지 않을 수 있다.
- **Flag:** 데이터 값이 반복 횟수·배열 크기·대기 시간을 상한 없이 결정 → HIGH.

### 4. 영속 저장 무결성
전제: 영속 저장
- **Flag:** 저장 파일 경로를 외부 입력으로 조합(경로 탐색 가능) → HIGH.
- **Flag:** 저장 중 중단 시 기존 저장이 손상되는 쓰기 방식(임시 파일·교체 없음) → MEDIUM.

### 5. 네트워크 전송
전제: 네트워크
- **Flag:** 암호화되지 않은 전송, 인증서 검증 우회 → CRITICAL.

### 6. 계정·인증
전제: 사용자 계정
- **Flag:** 인증 토큰을 평문 파일·설정 저장소에 보관 → CRITICAL.

### 7. 개발 전용 기능 노출
- **Flag:** 디버그 패널·치트 명령이 개발 전용 구역 밖에 있어 릴리스 빌드에 포함 → MEDIUM. 슬라이스 단계의 디버그 빌드 전용 기능이면 LOW.

### 8. 서드파티 의존성
- **Flag:** 서드파티 의존성 목록에 출처가 공식 레지스트리가 아니거나 버전이 고정되지 않은 패키지 추가 → MEDIUM.
- **Flag:** 목적이 불분명한 네이티브 플러그인·실행 파일 추가 → HIGH.

### 9. 출력 형식

```
### [CRITICAL|HIGH|MEDIUM|LOW] 한 줄 제목
- 위치: `파일:라인` 또는 `문서:절`
- 근거: 해당 판정 절(§N)과 실제 악용·사고 시나리오
- 제안: 무엇을 해야 하는지 (자격증명 유출이면 교체 필요 여부 포함)
```

발견 뒤에 SKILL.md §검사 커버리지 형식의 블록을 붙인다. 이 문서의 판정 절은 §1~§8, 비판정 절은 §9 이다.

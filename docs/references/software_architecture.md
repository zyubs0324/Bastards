# 소프트웨어 아키텍처 기준 (scope: arch)

> 논리명의 실제 표기는 활성 스택 문서 §1 을 따릅니다. 심각도 정의는 `README.md` 입니다.

## 0. 핵심 보정 원칙

- 판정 대상은 **경계와 방향**이다: 무엇이 무엇을 참조하는가, 상태를 누가 바꾸는가, 입력·시간·난수가 어디서 들어오는가.
- SOLID·DRY·KISS·YAGNI 는 규모에 맞춰 적용한다. 1인 프로토타입에서 **과설계도 결함**이다(§1.8).
- 기획서·설정집·활성 계획 문서의 규칙과 구조가 어긋나는 것도 아키텍처 결함으로 본다(§1.10).
- 성능·누수는 이 문서에서 판정하지 않는다(performance 위임).

## 1. 판정 기준

### 1.1 규칙 모듈의 엔진 독립성
- **Flag:** 규칙 모듈이 엔진 API·표시 계층·데이터 로더를 참조하거나, 엔진 참조 차단 설정이 꺼져 있음 → CRITICAL.
- **Flag:** 규칙 계산(데미지·상성·장착 판정·과부하 판정·승패 판정)이 표시 계층 코드 안에 있음 → HIGH.

### 1.2 모듈 참조 방향
- **Flag:** 스택 문서 §0 "모듈 구성" 과 다른 방향의 참조, 또는 모듈 간 순환 참조 → HIGH.
- **Flag:** 데이터 로더가 표시 계층을 참조 → HIGH.

### 1.3 입력 경로 단일화
- **Flag:** 사용자 입력이 명령 큐를 거치지 않고 규칙 모듈 상태를 직접 바꿈 → HIGH. 자동 판단과 수동 입력이 서로 다른 경로를 타면 결정론과 재현이 깨진다.
- **Flag:** 명령이 틱 경계가 아닌 임의 시점(프레임 중간)에 반영됨 → HIGH.

### 1.4 상태 소유권
- **Flag:** 규칙 모듈 밖에서 전투 상태를 바꿀 수 있게 노출(가변 컬렉션, 공개 세터) → HIGH. 밖으로는 상태 스냅샷만 준다.
- **Flag:** 표시 계층이 규칙 상태의 사본을 따로 갱신·보관해 두 상태가 어긋날 수 있음 → MEDIUM.

### 1.5 시간 모델
- **Flag:** 규칙 계산이 프레임 경과 시간·실시간 시계에 의존 → HIGH. 규칙은 고정 틱 단위로만 진행한다.
- **Flag:** 배속 기능이 틱 크기(1틱의 의미)를 바꾸는 방식으로 구현됨 → HIGH. 배속은 프레임당 틱 호출 횟수로만 조절한다.

### 1.6 난수 주입
- **Flag:** 규칙 모듈이 전역·정적 난수 공급자를 직접 사용 → HIGH. 시드 난수를 주입받는다.
- **Flag:** 하나의 전투에서 난수 소비 순서가 표시 계층 동작(연출·프레임 수)에 따라 달라짐 → HIGH.

### 1.7 데이터 경계
- **Flag:** 규칙 모듈이 데이터 파일 형식 전용 타입(역직렬화용 타입)을 직접 받음 → MEDIUM. 데이터 로더가 검증 후 규칙 모듈 자체 타입으로 변환한다.
- **Flag:** 규칙 모듈 안에서 파일·리소스를 읽음 → HIGH (§1.1 과 중복이면 §1.1 로 보고).

### 1.8 과설계
- **Flag:** 구현이 하나뿐이고 교체 계획도 없는 인터페이스·팩토리·추상 계층 → MEDIUM. 단 시드 난수처럼 테스트 대체가 목적인 인터페이스는 제외.
- **Flag:** 활성 계획 문서 "범위 밖" 기능을 위한 확장 지점·설정·빈 구현 → MEDIUM.
- **Flag:** 범용 이벤트 버스·서비스 로케이터·의존성 주입 컨테이너 도입 → MEDIUM.

### 1.9 책임 분리
- **Flag:** 한 타입이 규칙 계산·화면 출력·데이터 로딩 중 둘 이상을 겸함 → MEDIUM.
- **Flag:** 진입점 객체가 생성·연결 외에 규칙 로직을 보유 → MEDIUM.

### 1.10 기획 정합성
- **Flag:** 활성 계획 문서가 명시한 규칙·공식이 구조상 빠져 있거나, 기획에 없는 규칙이 임의로 추가됨 → HIGH.
- **Flag:** 같은 규칙이 두 곳 이상에 서로 다르게 구현되어 어느 쪽이 기획을 따르는지 불분명 → HIGH.

- **Note:** 메모리 누수·메인 스레드 블로킹·프레임당 할당은 performance 문서에 위임한다.

## 2. 출력 형식

발견마다 아래 형식으로 적는다. 심각도 순으로 정렬한다.

```
### [CRITICAL|HIGH|MEDIUM|LOW] 한 줄 제목
- 위치: `파일:라인` 또는 `문서:절`
- 근거: 해당 판정 절(§1.x)과 왜 해당하는지
- 영향: 방치하면 무엇이 깨지는지
- 제안: 무엇을 해야 하는지
```

발견 뒤에 SKILL.md §검사 커버리지 형식의 블록을 붙인다. 이 문서의 판정 절은 §1.1~§1.10, 비판정 절은 §0·§1(컨테이너)·§2 이다.

# 테스트 기준 (scope: test)

> 논리명의 실제 표기는 활성 스택 문서 §5 를 따릅니다. 심각도 정의는 `README.md` 입니다.

## 0. 핵심 보정 원칙

- 규칙 모듈과 데이터 로더는 **자동 테스트가 필수**다. 규칙이 게임의 재미를 결정하고, 수치 조정 때마다 회귀가 생기기 쉽기 때문이다.
- 표시 계층은 활성 계획 문서의 **수동 시나리오**로 검증한다. 표시 계층에 자동 테스트가 없는 것은 결함이 아니다.
- 결정론(같은 시드·같은 명령 → 같은 결과)은 이 프로젝트의 핵심 불변식이다. 방치형 오프라인 계산과 버그 재현이 여기에 기댄다.

## 1. 판정 기준

### 1.1 규칙 변경의 테스트 누락
- **Flag:** 규칙 모듈의 공식·판정을 추가·변경했는데 대응 테스트가 없음 → HIGH.
- **Flag:** 데이터 로더 검증 규칙을 추가·변경했는데 잘못된 입력 테스트가 없음 → MEDIUM.

### 1.2 결정론 검증
- **Flag:** 같은 시드·같은 명령열로 두 번 실행해 결과가 같은지 확인하는 테스트가 없음 → HIGH.
- **Flag:** 배속(프레임당 틱 수) 차이가 결과를 바꾸지 않는다는 검증이 없음 → MEDIUM.

### 1.3 경계값
- **Flag:** 임계치 경계(요구치와 정확히 같음·1 부족·크게 부족), 0·상한, 체력 정확히 0, 제한 시간 마지막 틱 케이스가 빠짐 → MEDIUM.

### 1.4 격리
- **Flag:** 테스트가 실시간 시계·전역 상태·실제 데이터 파일·실행 순서에 의존 → HIGH.
- **Flag:** 한 테스트가 여러 규칙을 동시에 검증해 실패 원인을 특정할 수 없음 → LOW.

### 1.5 확률 판정 제어
- **Flag:** 확률 규칙(크리티컬·과부하 분기) 테스트가 실제 난수로 돌아 가끔 실패할 수 있음 → HIGH. 고정 수열 난수로 각 분기를 강제한다.
- **Flag:** 과부하 4분기(성공·흩어짐·폭주·한계돌파) 중 테스트되지 않은 분기가 있음 → MEDIUM.

### 1.6 구조와 이름
- **Flag:** 테스트 이름이 검증하는 동작을 말하지 않음(예: `Test1`, `DamageTest`) → LOW.
- **Flag:** 준비·실행·검증 단계가 섞여 읽기 어려움 → LOW.

### 1.7 커버리지
- **Flag:** 규칙 모듈 라인 커버리지 80% 미만 → MEDIUM.
- **Flag:** 커버리지를 측정하지 않은 채 Phase 완료로 표시 → MEDIUM.

### 1.8 수동 시나리오 동기화
- **Flag:** 표시 계층 동작이 바뀌었는데 활성 계획 문서의 수동 시나리오가 갱신되지 않음 → MEDIUM.

### 1.9 에디터 플레이 테스트
전제: PlayMode 테스트
- **Flag:** 화면 흐름 자동 테스트가 실제 프레임 대기 시간(초 단위 대기)에 의존 → MEDIUM.

### 1.10 구현 세부 고정
- **Flag:** 테스트가 비공개 멤버를 우회 접근하거나 내부 호출 순서를 검증해 리팩터링마다 깨짐 → MEDIUM. 공개 입력·출력으로 검증한다.

## 2. 출력 형식

```
### [CRITICAL|HIGH|MEDIUM|LOW] 한 줄 제목
- 위치: `파일:라인` 또는 `문서:절`
- 근거: 해당 판정 절(§1.x)과 빠진 검증이 무엇인지
- 제안: 추가할 테스트 케이스(이름과 준비·기대값)
```

발견 뒤에 SKILL.md §검사 커버리지 형식의 블록을 붙인다. 이 문서의 판정 절은 §1.1~§1.10, 비판정 절은 §0·§1(컨테이너)·§2 이다.
